# Главный экран «Обзор»: состав, ресурсы, уведомления

Дата: 2026-08-18 · статус: согласовано в диалоге, ждёт реализации

## Зачем

Главная сейчас смешивает состояние шлюза, ресурсы и отладочную скорость моделей,
показывает неверный адрес в сети и не отвечает на главные вопросы владельца:
хватит ли квоты, не сгорит ли неиспользованная, что требует реакции. Уведомления
существуют как один глобальный тумблер с одним порогом — раздельного управления
по ресурсам нет вовсе.

## Состав экрана (сверху вниз)

1. **Статус шлюза** — состояние, порт, адреса, кнопка запуска (outline), QR-код
   адреса, кнопка «Проверить связь».
2. **«Требует внимания»** — блок присутствует только при активных условиях
   (те же пять триггеров, что у уведомлений) + «шлюз остановлен, есть попытки
   подключения». Каждая строка ведёт к действию.
3. **«Кто обслужит следующий запрос»** — активная модель, провайдер, причина
   выбора (пресет / правило / вручную / авто по скорости).
4. **Ресурсы провайдеров** — плитки одинаковой высоты, горизонтальная прокрутка.
5. **Три графика** — расход и прогноз · использование по дням · темп расхода квоты.
6. **Экономия на локальных моделях** — оценка за месяц.
7. **Живой поток запросов** — последние строки и запросов в минуту.

Скорость моделей с главной удаляется.

## Плитка ресурса

Фиксированные размеры: ширина 168.dp, высота 190.dp — плитки не «прыгают» при
разном наборе данных.

Содержимое:
- Шапка: логотип провайдера 16.dp + имя провайдера (крупно, 1 строка, эллипсис).
  Тип ресурса словом не подписывается — его несёт логотип и вид значения.
- Значение по типу: кольцо процентов (квота, свой бюджет) · сумма на счету
  (баланс) · иконка и «без лимита» (бесплатный).
- Подпись «сброс через N» — только для квоты.
- Строка «хватит до HH:MM» — из `tExhaust`, когда исчерпание наступает раньше
  сброса; иначе «сгорит ~X» — из `surplus`.
- Состояние передаётся цветом кольца/значения по шкале давления. Текстовых
  ярлыков «Квота · Критично» нет.
- Тап по плитке открывает шит уведомлений этого ресурса.

## Уведомления

Настройки хранятся на каждый пул отдельно в конфиге (`notify_<poolId>_*`) —
схема БД не меняется (в базе включён destructive fallback).

| Тип | Триггер | Значение по умолчанию |
|---|---|---|
| Квота | остаток ниже порога в % | вкл, 15 % |
| Квота | по прогнозу кончится раньше сброса | вкл (порогов нет, всё считается) |
| Квота | часть квоты сгорит неиспользованной («успей использовать») | вкл, значимость — 1 сутки обычного расхода |
| Квота | сброс произошёл, квота снова полная | вкл |
| Баланс | баланс ниже суммы | вкл, 5 USD |
| Бесплатный | нет триггеров | шит показывает одну строку «ресурс без лимита» |

### Расчёт вместо фиксированных процентов

Фиксированная доля остатка непригодна: 29 % у одного тарифа — сутки работы, у
другого — месяц. Оба темповых триггера считаются из собственной истории расхода
и оказываются двумя исходами одного сравнения.

Из истории снимков квоты (`QuotaSnapshot`, 90 дней) берём:

- `rAvg` — средний темп расхода за последние 24 ч (единиц квоты в час);
- `rPeak` — максимальный суточный темп за 30 дней: сколько владелец реально
  способен израсходовать, если возьмётся;
- `tReset` — часов до сброса; `remaining` — остаток.

Сравниваем время исчерпания с временем до сброса:

```
tExhaust = remaining / rAvg
```

- `tExhaust < tReset` → **кончится раньше сброса**. В уведомлении — ожидаемое
  время исчерпания и на сколько раньше сброса это произойдёт.
- `tExhaust > tReset` → **часть сгорит**: `surplus = remaining - rAvg * tReset`.
  Сообщаем, когда потеря значима и её ещё можно отыграть:
  - значимость: `surplus >= rAvg * 24` — сгорит больше, чем обычно уходит за
    сутки. Настройка триггера — это число суток (по умолчанию 1), а не процент;
  - своевременность: `surplus / rPeak <= tReset <= 4 * (surplus / rPeak)` —
    времени до сброса хватает на эту работу, но запас не больше четырёх сроков.
    Односторонняя проверка оказалась неверной: она срабатывала как раз в
    безнадёжном случае, когда остаток не выбрать при всём желании, и молчала,
    когда времени как раз достаточно.
  - Текст: сколько сгорит, сколько часов активной работы нужно, сколько осталось.

Если `rAvg` неизвестен (нет истории) или равен нулю — оба триггера молчат:
ничего не выдумываем. `rPeak` при отсутствии истории приравнивается к `rAvg`.

Каждое уведомление шлётся один раз на цикл: факт отправки помечается ключом
`notify_<poolId>_<trigger>_sentAt`, сбрасывается при сбросе квоты.

## Графики

| График | Что показывает | Источник |
|---|---|---|
| Расход и прогноз | накопленный расход месяца (тарифы + токены), пунктир прогноза, линия бюджета | `UsageHistory.forecast` / `daily`, `CodexAccount.monthlyPriceUsd` |
| Использование | токены и вызовы по дням (стек prompt/completion) | `UsageHistory.daily` |
| Темп расхода квоты | остаток квоты во времени и пунктир ровного темпа до сброса; линия ниже пунктира = сгорит неиспользованной, выше = кончится раньше | `QuotaSnapshotDao.getHistoryForPool` |

## Скорость моделей

- **Строка модели** (Ресурсы → Модели): время до первого токена, токены/с,
  кнопка «Тест» — там, где выбирают модель.
- **Активность**: тренд скорости по времени (уже есть) остаётся единственным
  местом с историей замеров.
- **Деталь модели**: шит по тапу — график скорости этой модели, цена, контекст,
  псевдоним, её расход.

## Отдельные исправления

- **Адрес в сети.** `localIpAddress()` берёт первый не-loopback адрес любого
  интерфейса, поэтому показывает адрес мобильной сети или VPN. Выбираем
  интерфейс, который поднят, не loopback, не point-to-point и имеет IPv4-адрес;
  приоритет — `wlan`/`eth`, затем прочие. Если подходящего нет — строка
  «нет сети», а не чужой адрес.
- **Кнопка запуска** — `OutlinedButton` вместо заполненной.

## Шесть добавлений

1. **Проверить связь** — последовательно: порт слушается, апстримы отвечают,
   у CLI-сессий валиден токен, есть интернет. Результат — список строк с
   состоянием, без модальных диалогов.
2. **QR-код** адреса шлюза. Требуется зависимость `com.google.zxing:core`
   (Apache 2.0); битмап рисуется своим кодом, без embedded-UI.
3. **Кто обслужит следующий запрос** — из `GatewayScheduler` (лучшая модель),
   принудительного выбора и активного пресета маршрутизации.
4. **Хватит до …** — прогноз исчерпания квоты из темпа за 24 ч (см. выше).
5. **Экономия на локальных моделях** — токены локальных провайдеров за месяц,
   пересчитанные по цене самой дешёвой доступной облачной модели. Помечается как
   оценка, эталонная модель называется прямо в подписи.
6. **Попытки подключения при остановленном шлюзе.** Оговорка: пока шлюз
   остановлен, порт никто не слушает, и узнать о попытках технически нельзя.
   Поэтому пункт реализуется как отдельный переключатель «тихий приёмник»:
   порт остаётся занят, на запросы отвечает `503` и считает попытки. По
   умолчанию выключен, чтобы поведение остановленного шлюза не менялось молча.

## Проверка

- Unit-тесты: выбор сетевого интерфейса (набор искусственных интерфейсов),
  расчёт триггеров уведомлений (пороги, «успей использовать», прогноз
  исчерпания, однократность на цикл), расчёт экономии, разбор темпа расхода.
- На устройстве: адрес совпадает с `adb shell ip route`, плитки одной высоты при
  разных данных, шит уведомлений открывается по тапу и сохраняет значения,
  графики рисуются на реальных данных двух аккаунтов Codex и Ollama.

## Вне объёма

- Окупаемость тарифа и итоги по циклам (обсуждались, не выбраны).
- Переезд остальных экранов; правки только по «Обзору», строке модели и
  детали модели.
