# Как участвовать

Спасибо за интерес к AiGate! Проект небольшой, правила простые.

## Окружение

Нужны JDK 17 и Android SDK (compileSdk/targetSdk 37). Движок llama.cpp
собирается из исходников, поэтому клонируйте с подмодулями:

```bash
git clone --recurse-submodules https://github.com/Mesteriis/ai-gate.git
# или в уже склонированном репозитории:
git submodule update --init --recursive
```

Для нативной части нужны NDK и CMake 3.31.6 — Android Gradle Plugin
скачает их сам через SDK Manager при первой сборке.

## Сборка и проверки

```bash
./gradlew assembleDebug              # debug APK
./gradlew lintDebug testDebugUnitTest # линт + юнит-тесты — обязательный гейт
./gradlew assembleRelease            # релизная сборка (подпись — по env, см. README)
```

Те же гейты CI запускает на push в `main` и на каждый pull request. Изменение считается
готовым, когда `lintDebug testDebugUnitTest assembleDebug assembleRelease`
зелёные. Линт настроен строго: `abortOnError = true`, известные старые
проблемы зафиксированы в `app/lint-baseline.xml` — не расширяйте baseline
под новые ошибки.

## Стиль

- Kotlin, отступ 4 пробела (см. `.editorconfig`).
- Язык проекта — русский: строки интерфейса, комментарии и сообщения
  коммитов пишутся по-русски.
- Коммиты — в духе Conventional Commits с русским описанием:
  `feat(виджеты): …`, `fix(шлюз): …`, `docs: …`, `test(квоты): …`.
- Комментарий в коде объясняет ограничение или причину, а не пересказывает
  следующую строку.

## Принципы, которые проект держит

- **Честные данные.** Отсутствие данных показывается прочерком или словом
  «недоступно», а не выдуманным нулём. Источник квоты всегда различим:
  данные провайдера ≠ локальный подсчёт ≠ оценка.
- **Безопасность по умолчанию.** Слушаем только loopback; LAN — отдельный
  осознанный режим с токеном. Секреты живут только в Android Keystore —
  ни в Room, ни в бэкапах, ни в логах.
- **Шлюз, а не комбайн.** Чат, агенты, память, OCR и прочие
  «потребительские» функции сюда не добавляются — это задача приложений,
  которые ходят в AiGate по API.

## Pull request

1. Форкните репозиторий, создайте ветку от `main`.
2. Сделайте изменение небольшим и сфокусированным; добавьте или обновите
   тесты на значимое поведение.
3. Прогоните гейты локально, заполните шаблон PR.
4. На PR автоматически запустится CI — он должен быть зелёным.
